# 설계 노트 — hwpx 수학 문항 은행 자동 검수

> 내부 인수인계 문서의 공개용 정리본. 구체 파일명·문항 id·검수 결과 수치는 제외했다.

## 목표

hwpx 문항 은행에서 자동으로 잡는 것:

- 문항 번호·id 오류, 중복 출제, 정답 누락, 보기 개수/중복 (13종 결정론 검사)
- 정답 ↔ 해설 결론 불일치 (SymPy 동치 검산)
- 범위형 결론(`0<k<2`)에서 정답 값의 유일성
- 수식 조판 결함 (연산자 고아형 `$k<$$-3$`, 괄호 짝)
- 쌍둥이문항(평가↔일반) 교차 무결성

## 전제 구조 — 문항 1개 = 2열 표 1개

좌열이 필드명, 우열이 값이라 추측 파싱이 필요 없다:

```
문항id / 본문 / 선택지1~5 / 정답 / 해설1~3 / 지식단위 / 난이도 / 학습행동영역 / 쌍둥이문항
```

`문항id` 접두 문자로 세트를 구분하고(평가측 U/S/C, 일반측 G),
`쌍둥이문항` 필드가 평가→일반 대응을 담는다 (단방향, 1:N 허용).

## 확정된 방향 — 그리고 버린 것

버린 것 (되살리지 말 것):

| 폐기 | 이유 |
|---|---|
| hwpx → PDF → 페이지 이미지 렌더링 | 필요 없음. 텍스트·수식·구조가 XML에 다 있다 |
| vision API로 쪽 검수 | 위와 동일. 토큰 비용 논의 자체가 무의미 |
| `lineseg` 쪽 좌표 추출 | `문항id`가 더 정확한 좌표다 |
| H2Orestart / LibreOffice 변환 | 렌더링을 안 하므로 폰트 리스크 통째로 소멸 |

> 참고: `lineseg` 레이아웃 캐시(vertpos/horzpos/horzsize)로 쪽 번호·판면 초과를
> 렌더링 없이 계산할 수 있다. 이 프로젝트엔 불필요하지만 조판 원고 검사엔 쓸 수 있다.
> 단 캐시라서 XML을 스크립트로 수정하면 stale — 편집 → 한글로 열고 저장 → 검사 순서 필수.

## 한글 수식 스크립트 문법 노트 (실제 관측 기준)

hml2sympy가 처리하는 것들은 README 참고. 설계상 요점:

- **`&`/`#` 처리가 핵심.** 해설의 여러 줄 수식이 `$b^{2} & =c^{2}-a^{2}# & =16$` 형태다.
  `#`로 줄을 나누고 `&`를 걷어내면 각 줄이 독립 등식이 된다. **마지막 줄이 결론값** — 검산의 앵커.
- 백틱(`` ` ``)과 `~`는 공백, `it`/`rm`은 서체 지정자 — 의미 없음.
- `CDOTS`는 수식이 아니라 나열 기호. 값 계산 불가 플래그로만 남긴다.
- 좌표 `F(4,0)`은 심볼 호출이 아니라 튜플이다. 라벨을 떼지 않으면
  implicit multiplication이 Symbol×tuple을 만들어 터진다.
- 비율 `a:b`는 등식 대조에서 `a/b`와 등가.
- sympy 전역 이름과 기하 점 이름이 충돌한다(O=Order, E=e, I=허수).
  화이트리스트 global_dict로 해결 — 없는 이름은 전부 심볼이 된다.

## 함정 / 주의

- **오탐이 세 번 나면 아무도 안 쓴다.** 애매하면 high로 올리지 말고 보고 없이 집계로 내린다.
- **인쇄된 정답을 뒤집는 판정은 단정하지 않는다.** 근거를 붙여 사람에게 넘긴다.
- **본문 XML을 LLM 컨텍스트에 올리지 말 것.** section XML은 수 MB다.
  스크립트가 파싱하고 요약만 출력한다.
- 중첩 표가 있다. 직속 자식 행/셀만 훑어야 필드가 안 섞인다 (`_own_rows`/`_own_cells`).
- 정규화에서 `{}`를 무조건 지우면 `k<{-{1}over{2}}`가 `k<`로 뭉개진다.
  문자열 정규화 대조의 고질 오탐 — SymPy 동치 판정으로 가면 해소된다.
- 해설의 부등식·`≠`는 **제약 조건**이지 결론 값이 아니다. 값 후보로 새면
  엉뚱한 보기가 일치한다. 범위 판정은 모든 제약의 교집합으로.
- 방정식형 보기(`x²/4−y²/5=1`)는 우변만 떼면 전부 `1`로 뭉개진다.
  관계식 전체를 차이식 기반으로 비교할 것.
- 쌍둥이 검사에 정답 번호 일치를 넣지 말 것 — 쌍둥이는 숫자를 바꾼 문항이라
  정답 번호가 자유롭게 달라진다. 실측으로 확인된 불변식만 검사한다.
- `해설2`, `해설3`은 대부분 비어 있다. 비었다고 결함이 아니다.

## 파싱 성공률 작업 순서 (재현용)

1. 전체 수식을 트랜스파일러에 넣어 성공/실패 집계 — **문법을 상상해서 만들지 말고**
   실패 패턴 상위 10개를 보고 보강한다.
2. 실패 군집을 "남은 대문자 키워드" 우선으로 묶으면 미지원 문법이 바로 보인다.
3. 성공률보다 **오탐 0**이 먼저다. 파싱 성공 = 검산 가능이지 검산 정답이 아니다.
